# Communications Plan — Omnichannel Customer Experience Programme

## Identified Stakeholders

See [`A-stakeholder-map.md`](./A-stakeholder-map.md) for the catalog. This plan defines the
communications each group requires from EA.

## Communications Needs

| Stakeholder group               | Needs                                                       |
| ------------------------------- | ----------------------------------------------------------- |
| Sponsor & Steering Cmte         | Programme heartbeat, RAID, financial position               |
| Architecture Board              | Phase deliverables, principle waivers, compliance findings  |
| Delivery teams                  | Target architectures, ABBs/SBBs, NFRs, decision rationales  |
| Risk / Audit / DPO / CISO       | Compliance evidence, controls mapping, change requests      |
| Business unit ops               | Operational changes affecting them, training needs          |
| Group communications            | Talking points for colleague comms                          |

## Communications Channels

| Channel                            | Use                                                  | Cadence       |
| ---------------------------------- | ---------------------------------------------------- | ------------- |
| Steering Committee deck            | Programme heartbeat                                  | Monthly       |
| Architecture Board minutes         | Decisions, waivers                                   | Fortnightly   |
| EA Platform dashboard (this app)   | Live ADM RAG, deliverable status, sign-offs          | Continuous    |
| Programme Confluence space         | Working drafts, RAID, glossary                       | Continuous    |
| Group town hall                    | Major milestones                                     | Quarterly     |
| Team Slack channels                | Day-to-day clarifications                            | Continuous    |
